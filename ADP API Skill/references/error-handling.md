# ADP API 错误处理

## 认证

- 401/403 或 `Accessor not found`：换另一个区域 Base URL 重试一次。
- 两个区域都认证失败：报告 Key 错误、过期、禁用或环境不匹配。
- 认证成功后不要再切换区域；后续请求沿用成功的区域。

## 网络和服务错误

- 连接失败、超时、502/503/504：有限次数退避重试。
- 同步抽取/解析响应超时、截断或无法解析时，不要因为“没有 task ID”就判定未执行；同步接口可能本来就不返回任务 ID。先保留完整 HTTP 状态、响应头、响应体片段和客户端请求标识，必要时联系平台核对扣费。
- 异步创建任务的 POST 请求超时后，不要立即重复提交；先查询是否已生成 task ID 或 run ID。若没有任何服务端标识，标记为 `submission_unknown`，禁止自动重提，避免重复扣费。
- 4xx 参数错误：修正请求，不重试原请求。

## 业务错误

- 必须同时检查 HTTP 状态码、顶层 `code`、`message` 和 `data`。
- HTTP 200 但业务 `code` 非 success 时，应按失败处理。
- 积分不足或额度耗尽：停止任务提交，明确提示当前区域，并给出当前 `base_url` 作为登录/充值入口：`https://adp.laiye.com` 或 `https://adp-global.laiye.com`。不要继续重试，也不要切换到另一区域绕过额度限制。
- 应用不存在或无权限：刷新应用列表，并要求用户确认正确的 app_id；不要自动创建应用。
- 工作流处于草稿/版本未指定：先查询版本信息并优先选最新已发布版本，运行请求带上 `release_version_id`。不能把 Web 端草稿可运行推断为 API 端也可运行；若 API 拒绝草稿，报告版本状态和原始错误。

## 工作流版本选择

- `application_id` 只标识应用，不等于应运行的发布版本。
- 运行前读取官方文档定义的应用详情或版本列表接口，过滤 `published`/“已发布”等成功发布状态。
- 按发布时间、发布时间戳或可比较的版本号降序选择最新发布版本；保存版本 ID、状态和选择依据。
- 如果用户指定了明确的 `release_version_id`，遵循用户指定，但仍校验该版本属于目标应用且状态可运行。

## 并发和批量

- 单个小文件（目标 <10 秒）优先同步；批量短文件可按最多 10 个同步请求并发执行，受限后降为 2。
- 异步批量默认最多 10 个并发；若 API 明确返回并发限制，降低并发后只处理尚未提交的文件。
- 每个文件保存 `source_file`、`file_id`、`task_id/run_id`、`status`、耗时和结果；同步成功时任务字段可为空。
- 不要因单个文件失败而丢弃整个批次；最终报告成功、失败和未完成数量。

## 积分已扣但结果失败

- 先区分：请求被业务拒绝、请求已接受但处理失败、客户端超时导致提交状态未知。
- 只要创建/提交响应显示成功，或能拿到任务标识，就禁止重新提交同一文件；继续查询原任务或报告原任务错误。
- 没有任务标识时，不声称“肯定扣费”或“肯定未执行”。报告 `submission_unknown`，保留时间、应用、文件和错误信息，提示用户到 ADP 当前区域核对运行记录/积分；确认未生成任务后再人工重试。
