# 飞书订单工作台结构

`scripts/init_lark_workspace.py --config config.json` 会创建一套可直接演示的飞书 Base 工作台，并把资源 ID 回写到 `config.json`。待审核表面向业务人员，不写 ADP 原始字段；开发排障使用本地 `work/adp-order-json/` 中的原始识别结果。自动预审由 Base 公式完成：公式读取商品匹配表和历史订单表，生成来也 SKU、标准价、历史订单数、报价有效期、价差、`审核状态` 和 `审核说明`；脚本只写入订单基础字段，并在写入后回查 Base 公式结果用于通知。

## 创建内容

- Base：默认名称 `ADP 采购订单自动审核`
- 表 1：`商品匹配表`
- 表 2：`历史订单表`
- 表 3：`待审核订单表`
- 仪表盘：`全流程订单管理仪表盘`
- 审核负责人私信：默认把当前飞书 user 写入 `审核负责人`，订单录入后给该人员发送结构化私信

初始化脚本会先创建业务表，再删除飞书默认空表。不要先删除默认表，否则飞书会报“最后一张表不能删除”。

## 商品匹配表

用于把客户订单里的客户订单商品号、厂家型号或描述映射为内部可审核的商品主数据。

初始化默认写入 14 条样例数据：保留 4 条与包内 demo PDF 对应的通用订单样例，再补入参考工作台中的 10 条电子元器件编码、品牌、标准价和报价有效期样例。

关键字段：

- `客户名称`
- `客户订单商品号`
- `来也 SKU`
- `商品名称/规格`
- `标准售价 USD`
- `币种`
- `报价有效期`
- `供应商/品牌`
- `状态`

## 历史订单表

用于判断客户是否历史合作过、价格是否偏离历史区间、订单是否有复购背景。

初始化默认写入 15 条历史订单数据：覆盖华为、深圳麦米、比亚迪、大疆、宁德时代、立讯精密等客户，以及包内 demo 所需的跨语种订单历史。

关键字段：

- `历史订单编号`
- `客户名称`
- `订单日期`
- `客户订单商品号`
- `来也 SKU`
- `数量`
- `成交单价USD`
- `成交金额USD`
- `审核结果`
- `来源文件`

## 待审核订单表

一条商品明细写入一条记录。多行订单会拆成多条记录，但保留同一个订单编号和来源文件。

字段分组：

- 订单基础：`订单编号`、`订单日期`、`卖方名称`、`买方/客户名称`、`买方/客户地址`、`收货方名称`、`客户收货地址`、`币种`、`订单总金额`
- 商品明细：`客户订单商品号`、`商品名称/规格`、`数量`、`税率`、`单价（含税）`、`总金额（含税）`、`交货日期`
- 来源追溯：`来源文件`、`订单源文件`、`来源邮件ID`、`来源邮箱`、`来源邮件主题`
- 审核结果：`审核状态`、`审核说明`、`审核负责人`、`人工审核动作`
- Base 公式字段：`来也 SKU`、`客户历史订单数`、`标准售价 USD`、`报价有效期`、`上次成交价USD`、`价差百分比`、`审核状态`、`审核说明`
- 流转管理：`流转状态`、`已写入历史`
- 去重：`明细唯一键`

兼容字段：`订单币种`、`单价含税`、`总金额`、`到货日期` 会继续保留给现有公式和自动化使用，但默认业务视图不展示这些旧命名字段。

初始化默认创建业务视图：

- `审核工作台`：给审核人使用，前三列固定为 `订单编号`、`审核状态`、`审核说明`，后续只展示订单日期、买方、金额、币种、商品明细、源文件、负责人、人工动作和流转状态，并过滤掉 `归档` 记录。

## 公式计算

`审核负责人` 是人员字段。初始化脚本会尝试读取当前飞书 user open_id，并把演示待审核记录默认分配给当前用户；如果没有 user 授权，则字段仍会创建，但演示记录不写负责人。

`订单源文件` 是附件字段。脚本会把本地订单或邮箱下载的原始订单 PDF/图片上传到这一列。邮箱附件会先缓存到 `work/mail-order-attachments/`。审核通知中的“原文链接”指向待审核记录，审核人打开记录即可看到订单源文件附件。

初始化会创建这些辅助公式字段：

- `来也 SKU`：按 `客户订单商品号` 从 `商品匹配表.客户订单商品号` 匹配内部编码。
- `标准售价 USD`：按 `客户订单商品号` 从商品匹配表取标准价。
- `报价有效期`：按 `客户订单商品号` 从商品匹配表取报价有效期。
- `上次成交价USD`：按客户和客户订单商品号从历史订单表取最近成交价。
- `客户历史订单数`：统计该买方在历史订单表中的历史记录数。
- `价差百分比`：计算当前订单价与标准价的偏离比例。
`审核状态` 和 `审核说明` 是 Base 公式字段。脚本写入订单后必须回查公式结果，再用回查结果发送通知，避免通知卡片和 Base 展示结论不一致。

## 演示数据

默认写入脱敏演示数据，并与 `demo-data/orders/` 中的 4 份可上传 PDF 对应。覆盖：

- 商品匹配表 14 条
- 历史订单表 15 条
- 待审核订单表 5 条
- 正常通过审核
- 新客户
- 客户订单商品号未匹配
- 多行订单部分匹配、部分未匹配
- 报价有效期过期
- 单价与商品匹配表标准售价不一致

对应文件：

- `LYCN-PO-202606-001_BlueOcean_MFG.pdf`
- `LYVN-PO-202606-018_SaoViet_Electronics.pdf`
- `TH-NW-2026-0620_NewWave_Automation.pdf`
- `LYDE-PO-202606-019_Rheinwerk_Robotics_GmbH.pdf`

如果用户明确想要空表，使用：

```bash
python3 scripts/init_lark_workspace.py --config config.json --skip-demo-data
```

正式使用前，用户需要把演示数据替换成自己的业务数据：维护 `商品匹配表`、导入 `历史订单表`、确认审核负责人，并按实际价格规则调整 `settings.price_variance_threshold` 或脚本里的预审规则。

## 仪表盘

`全流程订单管理仪表盘` 用来展示端到端效果，不承担复杂 BI。默认包含：

- 待审核订单总数
- 历史订单总数
- 待审核订单总金额
- 历史订单商品总数量
- 历史订单数量趋势
- 待审核订单状态分布
- 全流程订单管理说明
- 客户订单金额，按 `买方/客户名称` 聚合 `总金额（含税）`，同一家公司只出现一次
- 历史订单客户排行

## 自动归档

初始化会创建 `审核通过订单自动归档工作流` workflow。审核人确认订单各项通过后，把 `流转状态` 改为 `归档`，workflow 会把该记录复制到 `历史订单表`，并把原记录的 `已写入历史` 勾选为 true。`审核工作台` 会过滤 `归档` 记录，因此业务上表现为从待审核挪到历史订单表；原记录仍保留用于追溯和防重复归档。

如果飞书仪表盘 API 权限不足，脚本应保留表结构和记录写入结果，并在输出里标注仪表盘创建失败原因。
